## API and compatibility boundary

`FiniteTwoPlayerRootSequenceBatch.solve(game, questions)` captures the external
game once and returns an opaque result only after every question succeeds. Its
`audit().minima()` preserves caller order. The immutable result has no public
constructor; deserializing an audit cannot supply the owned parent required by
the internal borrowing path. A parent from another game or solver mode rejects
before endpoint work. Duplicate questions, unknown actions, later or insufficient-
reach questions and original topology/recall violations reject during preflight.

Eight is a maximum question count, not a promise that every eight-question game
fits the unchanged compiler/pivot/arithmetic caps. Exhausting any cumulative
endpoint budget fails the complete operation; limits do not reset per question
and no partial result is published. Parent compilation and its two original LPs
retain their separate original limits. Each endpoint may use a different
opponent/continuation witness. Sharing the parent does not turn those extrema
into one coherent whole-hand policy, action-frequency chart or full EV interval.

The existing standalone root-minimum path keeps its algorithm, gates, matrices,
work accounting and serialized audit. Its original 19 analytic tests and complete
12-test physical-study replay pass. The physical replay reproduced the entire old
report, including the original parent, references, comparison and minimum, without
changing any saved source or trainer answer. Public APIs, website routes, cache
pins and source admission are unchanged. There is no new HTTP route or lesson.
