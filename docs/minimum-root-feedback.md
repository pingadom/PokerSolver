All three fresh/owned policies passed the unchanged gates and the new complete-menu
bounds, with zero utility or loss bound violation. The result qualifies for an
offline drill; public trainer admission remains false.

Every full-action upper bound is retained. The fold and call moves are exactly

## Validation and use

The Java regression class shares one complete physical replay, then checks source
identity, complete menu/loss derivation, all policy gates, unchanged classifications,
private ownership, strict inputs and immutable outputs. Controls reject a minimum
upper bracket used as an action ceiling and preserve outside-face/quality failures.
A separate parsing-only Java guard confirms that JSON cannot construct either
owned capability class; it performs no physical replay. The independent Python
checker verifies the pinned original source and minimum,
then reconstructs all menu, policy and qualification fields without optimization.

```text
mvn -pl solver -Dtest=RootMinimumFeedbackTest test
python -m unittest discover -s scripts -p test_check_root_minimum_feedback.py
```

The command entry point is `com.pokerlab.solver.SixMaxRootMinimumFeedbackMain`:

```text
solve|replay feedback-request original-envelope original-minimum feedback-report
```

It rejects existing generation outputs and aliases before physical work. Minimum
source bytes are captured once, bounded and pinned before decompression; the old
envelope retains its own byte/canonical checks. The complete original minimum
must match an owned physical reproduction before feedback qualification begins.
A private `QualifiedFeedback` object binds the complete resulting report hash;
parsing a report creates no such object.

The current website/cache/API still uses the existing root-preflop source. Wiring
this separate qualification into a typed source loader and cached trainer is the
next boundary, with separate source pins, ownership/admission tests and a declared
startup-replay budget. This result is not a broader six-active-player solution.
