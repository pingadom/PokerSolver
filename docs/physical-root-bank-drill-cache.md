# Owned physical root-bank trainer cache

This offline loader carries the physical parent reuse result into the existing
three-hand research trainer cache. It performs one complete owned startup replay:
one physical game, one parent call/two parent LPs, fifteen endpoint LPs, and fresh
80k/160k references. Earlier startup used eight parent LPs. This is
a reduction in parent LP count; no comparative runtime speedup is claimed.

The owner reviewed and cleared code revision `0c134ab` on 2026-11-15.
Full PR CI follows this actual clearance. The approval at the end of this file
identifies the exact reviewed code revision.

## Two identities, one unchanged public contract

The existing mathematical/public source remains
`e333144323609afd2d5fd47daf7b2636b56647d3f080c579d1491c10afc8e84d`.
The separate physical reuse proof is
`feb331638b447a30be52d8fd9bfe6c267120afe29ba0b51c94b416f7d068771e`.
The new manifest binds both identities, all three exact input byte hashes and the
complete two-parent startup reservation. A fresh proof identity cannot substitute
for the public study ID when selecting questions or grading attempts.

The factory accepts only `SixMaxPhysicalRootBankStudy.Result`, whose constructor
is private. A parsed report, snapshot or true JSON flag cannot create cache
authority. The full physical replay must reproduce the captured report before
the factory uses its unchanged historical source to build the public projection.
The old factory and loader remain available and retain their original behavior.

All three original private hands, six-seat public tables, empty preflop boards,
nine legal grades and mixed ordered/repeated review results are preserved. No
villain cards or future community cards are exposed. The posted BB commitment
is added exactly once to current-decision EV; loss bounds, unresolved raises and
classifications stay unchanged. The immutable cache serves questions, grades and
reviews without loading files or running numerical work after startup.

The old public HTTP fixture still describes its historical eight-parent startup
reservation. It is unchanged source evidence, not a statement that the new loader
performed eight solves. This slice does not wire the new loader into HTTP, change
public metadata or replace the separately qualified tighter 77/AJs source.

## Captured inputs and bounded work

The manifest is strict JSON capped at 16 KiB. Dependency names are safe basenames;
request input is capped at 128 KiB and stored/expanded reports at 8 MiB. Symbolic
sources, directory inputs, escapes and hard-link aliases are rejected. Stored
pins, typed source hashes and full lineage are checked before numerical work.

The loader writes only its captured bytes into a new private temporary directory,
replays that view, then rechecks every original file's real path, file identity,
size, modification time and exact bytes. No live dependency path is reopened for
solving. Cleanup deletes only the three fixed temporary children and their exact
parent directory; it does not recursively delete a computed path. Any mismatch
returns no cache. Existing compiler, pivot and arithmetic caps are unchanged.

The single declared local cache suite completed in 90.407 seconds including Maven.
The owned cache class ran twelve cases using one startup; ten IO/manifest controls
and one pure typed-pin test also passed. All 23 cases passed without skips. No
numerical rejection was retried, no new public fixture was generated, and every
one of the 439 earlier data files and 28 resources retains its original bytes.

## Independent verification

The new checker pins and composes the existing physical and public cache checkers.
It independently verifies the original literal payoffs, certificates and policy
checks through those immutable helpers, the physical two-parent proof, both source
identities, all nine public grades, hidden-information boundaries and the canonical
mixed review. It performs no LP optimization or CFR training. Seventeen corruption
checks cover budget and identity substitution, false reuse accounting, incomplete
inventories, changed grades, future cards, review identities and canonical bytes.

The original physical report digest is derived from raw lexical JSON with only
out-of-string whitespace removed, preserving Java's number formatting and signed
zero. Existing public metadata remains historical; the new manifest records actual
startup provenance separately. The receipt has no grading or admission authority.

The initial checker test run found a wrong helper argument count; it was corrected
and the corruption tests now require an explicit validation error. Export checking
was tightened to read raw UTF-8 bytes, preserving CRLF corruption. The earlier
receipt and failed logs are retained locally. Neither correction reran the solver.

Run the new independent checks with:

```text
python scripts/check-physical-root-bank-drill.py
python -m unittest discover -s scripts -p test_check_physical_root_bank_drill.py
```

The owned loader entry point is
`SixMaxPhysicalRootBankDrillLoader.load(manifestPath, publicStudyHash)`.
Calling it performs the declared full startup work. Reading a manifest alone does
not grant ownership. CI adds the checker and its tests to the existing independent
step. All 30 jobs, timeouts and 389 earlier class assignments remain unchanged;
three new suites are automatically assigned, with the sole physical startup on
solver-7. No API, frontend, dependency or numerical library is changed.

## Scope and next step

This remains a conservative, supplied-range, fixed-prefix game with two active
players at six seats. Trainer admission is false. It does not establish unrestricted
six-player GTO, larger ranges, realistic rake or coherent full-hand play. Next,
add a separately reviewed opt-in backend configuration that reports the optimized
startup provenance accurately while preserving public lesson and grade identity.
AWS deployment remains paused.
