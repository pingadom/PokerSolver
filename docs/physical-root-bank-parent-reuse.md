# Physical hand bank with one owned parent

The new offline study reproduces the original three-hand preflop bank using the
parent already solved by the physical producer. The fixed supplied joint game,
folded-card blockers, selected-flop continuation, full opponent security face,
all three menus and original reference checks are unchanged. The completed run
uses two parent LPs instead of the original eight. Its fifteen endpoint LPs and
fresh 80k/160k CFR references remain mandatory. This is a reduction in repeated
solving, with no new public trainer content or stronger strategy claim.

## Owned handoff

The physical producer retains its actual private affine solver result alongside
its unchanged report. Only a package-level method can pass that handle to the
root batch. The reused-parent mode checks the algorithm and captured snapshot
hash, then checks every root and computes all envelopes under the original caps.
The separately tagged batch audit records zero additional parent calls, LPs or
parent compiler work because those belong to the physical producer. The physical
report retains the original parent witnesses and accounts for its two LPs once.

The ordinary batch path still solves one parent itself and retains its original
algorithm identity, audit and frozen analytic capture. Standalone envelope callers
keep their earlier calculations. A parsed report, null parent, unrelated game or
older parent algorithm cannot supply an owned parent handle. No new public API or
network endpoint is introduced.

## Independent verification

The independent checker first verifies the unchanged original physical bank:
its literal payoffs, original parent and endpoint certificates, grouped best
responses, full reference checks and complete gate outcomes. It then binds the
new physical parent and all fifteen endpoint certificates to that evidence with
exact typed and binary64 comparisons, allowing only the remaining compiler-limit
metadata to differ. All nine moves, nine policy checks, 27 forced continuation
values and 27 decision losses retain their original evidence. The checker performs
no LP optimisation or CFR training.

Original envelope hashes are independently derived from immutable raw source JSON
spans, removing only whitespace outside strings. This preserves Java's numeric
lexemes, signed zero and string contents rather than relying on Python's float
formatting. The complete raw canonical bank digest is checked first. Supplied
comparison hashes cannot vouch for themselves. Scope, source IDs, parent reuse,
all aggregate counters and remaining work caps are also checked.

## Scope and next boundary

This is the original supplied-range, fixed-prefix, two-active-player constant-sum
game at six seats. It does not establish unrestricted six-player GTO, richer
ranges or betting, realistic rake, attained action maxima or coherent full-hand
play. The conservative original three-hand menus are preserved; the separately
qualified tighter 77/AJs source is not replaced or downgraded. Existing caches
and website lessons keep their pins and grades. Trainer admission remains false.
Next integrate a separately pinned owned source where appropriate, retaining
qualification and public projection boundaries. AWS deployment remains paused.
